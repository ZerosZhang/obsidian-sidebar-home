# 开发记录：隐藏样式功能

> **2026-10-29 更新**：Markdown 格式符号隐藏（**、*、==、~~、`、\、#）及其 7 个设置项已移除，本文相关章节仅作历史记录。HTML 标签隐藏与空格可视化仍在用。

## 需求概述

将 MDRazor 插件的"隐藏 Markdown 格式符号"功能移植到 SideHome 插件，并额外支持隐藏 HTML 标签（`<strong>`、`<del>`、`<font>`、`<mark>` 等可配置列表）。

### 功能清单

| 功能 | 说明 |
|------|------|
| 隐藏加粗 `**` | `Decoration.replace` 隐藏标记符号 |
| 隐藏斜体 `*` | 同上 |
| 隐藏高亮 `==` | 同上 |
| 隐藏删除线 `~~` | 同上 |
| 隐藏行内代码 `` ` `` | 支持多反引号 |
| 隐藏转义 `\` | 仅隐藏反斜杠 |
| 隐藏标题 `#` | 支持 H1-H6，`#` 后无空格时不隐藏 |
| 隐藏 HTML 标签 | 可配置标签列表（默认 strong,del,font,mark） |
| 空格可视化 | 半透明 `·` 标记 |
| 光标修正 | 点击格式边界时自动推到标记外 |

## 最终方案

### 架构设计

参考 MDRazor 的 MVC 架构，新增两个 CM6 ViewPlugin 模块：

```
settings.ts          — 扩展设置接口（+10 个隐藏样式配置项）
format-hider.ts      — 隐藏格式符号 + HTML 标签（ViewPlugin + Prec.high）
whitespace-visible.ts — 空格可视化（ViewPlugin）
main.ts              — 注册扩展、配置同步、repaint 机制
setting-tab.ts       — 新增第三个 Tab「样式隐藏」
styles.css           — 空格可视化样式
```

### 配置同步机制

采用 MDRazor 的共享可变对象模式：

```
用户修改设置
  → saveSettings()
    → saveData()          // 持久化到磁盘
    → syncConfig()        // Object.assign 写入模块级对象
    → repaintAllEditors() // dispatch({}) 触发 ViewPlugin.update()
      → buildDecorations() // 从 formattingConfig/spaceConfig 读取最新值
```

ViewPlugin 实例生命周期与 Obsidian Plugin 生命周期解耦，无需重建或重新注册扩展即可使设置即时生效。

### Markdown 格式隐藏

使用 CM6 语法树（`syntaxTree(view.state).iterate()`）遍历节点，按节点类型名匹配格式：

- `formatting-strong` → 加粗（markerLen=2）
- `formatting-em` → 斜体（markerLen=1）
- `formatting-highlight` → 高亮（markerLen=2）
- `formatting-strikethrough` → 删除线（markerLen=2）
- `formatting-code` + `inline-code` → 行内代码（可变长度）
- `Escape`/`formatting-escape` → 转义（markerLen=1）
- `formatting-header`/`HeadingMark` → 标题（可变长度，需 `#` 后有空格）

对每个匹配节点，添加 `Decoration.replace` 装饰：
- 起始标记：`node.from` 到 `node.from + markerLen`，spec 携带 `markerType: 'open'`
- 结束标记：`node.to - markerLen` 到 `node.to`，spec 携带 `markerType: 'close'`
- 例外：转义和标题只有起始标记

### HTML 标签隐藏

**不依赖语法树节点类型名**，直接用正则扫描整个文档文本：

```typescript
const scanRegex = new RegExp(`<\\/?(${tags.join('|')})\\b[^>]*>`, 'gi');
const fullText = view.state.doc.sliceString(0, view.state.doc.length);
let match: RegExpExecArray | null;
while ((match = scanRegex.exec(fullText)) !== null) {
    decoItems.push({ from: match.index, to: match.index + match[0].length, deco: htmlHideDeco });
}
```

使用 `Decoration.mark({ class: 'sh-html-tag-hidden' })` 给标签字符加类，由 CSS 把字号归零隐藏（早期用 `Decoration.replace`，Obsidian 1.14 起会连带吞掉标签内容，见错误 8）。

### 装饰顺序

所有装饰（HTML + Markdown）统一收集到数组，按位置排序后添加到 `RangeSetBuilder`，避免顺序问题：

```typescript
decoItems.sort((a, b) => a.from - b.from || a.to - b.to);
const builder = new RangeSetBuilder<Decoration>();
for (const item of decoItems) {
    builder.add(item.from, item.to, item.deco);
}
```

### 光标修正

复用 MDRazor 的 `correctCursorAfterClick` + `adjustCursor` 模式：
- 检测 `select.pointer` 事件（鼠标点击）
- 查询装饰集，若光标在 `open` 标记右侧 → 推到标记左侧
- 若光标在 `close` 标记左侧 → 推到标记右侧
- 使用 `queueMicrotask` 异步执行修正，不干扰原始事务

### 空格可视化

使用 `WidgetType` 子类 `SpaceWidget`，将空格替换为 `<span class="sh-space-char">·</span>`。仅遍历 `view.visibleRanges`，性能开销极低。

## 踩坑记录

### 错误 1：HTML 标签隐藏无效——依赖语法树节点类型名

**做法**：遍历语法树，检查节点类型名是否为 `htmlTag` 或 `HtmlTag`，匹配则应用 `Decoration.replace`。

**问题**：Obsidian 的 CM6 语法树中，HTML 标签的节点类型名并非标准的 `htmlTag`/`HtmlTag`，导致匹配不到任何节点。

**调试方式**：将 CSS 改为红色背景（`background-color: red`），确认装饰完全没有生效。

**解决**：放弃依赖节点类型名，改为直接用正则扫描整个文档文本：

```typescript
const scanRegex = new RegExp(`<\\/?(${tags.join('|')})\\b[^>]*>`, 'gi');
const fullText = view.state.doc.sliceString(0, view.state.doc.length);
```

**教训**：不要假设语法树节点类型名与文档一致。对于需要精确匹配文本内容的场景，正则扫描比语法树遍历更可靠。

---

### 错误 2：HTML 标签正则扫描只覆盖可见范围

**做法**：用 `view.visibleRanges` 限制正则扫描范围，减少性能开销。

**问题**：用户查看的文本可能不在 `view.visibleRanges` 返回的范围内（实时预览的可见范围计算可能与预期不同）。

**解决**：改为扫描整个文档（`view.state.doc.sliceString(0, doc.length)`）。对于正常大小的文档，性能影响可忽略。

---

### 错误 3：Decoration.mark + CSS 隐藏 HTML 标签无效

**做法**：用 `Decoration.mark({ class: 'sh-html-hidden' })` 给 HTML 标签添加 CSS 类，设置 `display: none` 隐藏。

**问题**：`display: none` 在 CM6 的 Decoration.mark 中不生效。CM6 的装饰系统对 `display: none` 的处理与普通 DOM 不同，可能导致布局计算异常。

**调试方式**：确认正则匹配成功（红色背景可见），但 `display: none` 无法隐藏内容。

**解决**：改用 `Decoration.replace({})` 直接从 DOM 中移除内容，与 Markdown 格式隐藏的方式一致。

**教训**：CM6 的 `Decoration.mark` 不等同于普通 CSS。`display: none`、`visibility: hidden` 等可能导致不可预期的行为。需要隐藏内容时优先用 `Decoration.replace`，但如果该区间可能被宿主自己 replace（如 Obsidian 的内联 HTML widget），必须改用 mark + 字号归零（见错误 8）。

---

### 错误 4：RangeSetBuilder 装饰顺序问题

**做法**：先添加 HTML 正则扫描的装饰，再添加语法树遍历的 Markdown 装饰。

**问题**：`RangeSetBuilder` 要求装饰按位置严格递增添加。HTML 扫描覆盖整个文档，Markdown 遍历也覆盖整个文档，两者的位置可能交错，导致 builder 报错或产生错误结果。

**解决**：将所有装饰收集到数组，按 `from` 排序后统一添加：

```typescript
const decoItems: Array<{ from: number; to: number; deco: Decoration }> = [];
// ... 收集 HTML 和 Markdown 装饰
decoItems.sort((a, b) => a.from - b.from || a.to - b.to);
const builder = new RangeSetBuilder<Decoration>();
for (const item of decoItems) {
    builder.add(item.from, item.to, item.deco);
}
```

**教训**：混合多种装饰来源时，必须统一排序后再添加到 `RangeSetBuilder`。不要假设不同来源的装饰位置不会交错。

---

### 错误 5：TypeScript 类型错误——`@codemirror/language` 缺失

**做法**：直接 `import { syntaxTree } from '@codemirror/language'`。

**问题**：`package.json` 的 devDependencies 中没有 `@codemirror/language`，TypeScript 报错 `Cannot find module`。

**原因**：esbuild 配置将 `@codemirror/*` 标记为 external（由 Obsidian 运行时提供），所以不需要作为运行时依赖。但 TypeScript 类型检查需要类型声明文件。

**解决**：安装类型声明包：

```bash
npm install --save-dev @codemirror/language
```

**教训**：esbuild 的 `external` 只影响打包，不影响类型检查。对于 Obsidian 提供的 CM6 包，仍需安装 devDependencies 以获取类型声明。

---

### 错误 6：TypeScript 类型错误——设置项动态索引

**做法**：

```typescript
const formatToggles: Array<{ key: keyof typeof this.plugin.settings; label: string }> = [...];
for (const { key, label } of formatToggles) {
    this.plugin.settings[key] = value;  // TS2352
}
```

**问题**：`keyof typeof this.plugin.settings` 在解构后被 TypeScript 推断为 `string`，无法直接用于索引 `SidebarHomeSettings`。

**解决**：使用双重类型断言：

```typescript
(this.plugin.settings as unknown as Record<string, boolean>)[key] = value;
```

**教训**：TypeScript 对解构后的联合类型索引支持有限。需要动态索引时，使用 `as unknown as Record<string, T>` 是常见的绕过方式。

---

### 错误 7：输入 `![[]]` 时 `![[` 被隐藏——`formatting-em` 子串匹配误伤

**现象**：在 Obsidian 实时预览中输入 `![[]]`（嵌入/Wiki 链接语法），`![[` 被隐藏，只剩 `]]` 可见。

**原因**：`format-hider.ts` 第 139 行对斜体标记的判断使用了 `typeName.includes('formatting-em')`。Obsidian 的 CM6 解析器为 `![[` 嵌入语法生成的节点类型名包含 `formatting-embed`，而 `'formatting-embed'.includes('formatting-em')` 为 `true`——`formatting-embed` 的字符串前缀完整包含了 `formatting-em`。

```typescript
// Bug：formatting-embed 包含 formatting-em 子串，被误匹配
} else if (formattingConfig.hideItalicFormatting && typeName.includes('formatting-em')) {
    markerLen = 1;
}
```

匹配后 `markerLen = 1`，代码将嵌入节点的首尾各 1 个字符用 `Decoration.replace` 隐藏，导致 `![[` 中的字符被隐藏。

**默认触发**：`hideItalicFormatting` 默认为 `true`（`settings.ts:122`），所以该 Bug 任何用户都会遇到。

**解决**：增加排除条件 `!typeName.includes('formatting-embed')`，防止嵌入符号被误匹配为斜体：

```typescript
// 修正：排除 formatting-embed，防止误匹配
} else if (formattingConfig.hideItalicFormatting && typeName.includes('formatting-em') && !typeName.includes('formatting-embed')) {
    markerLen = 1;
}
```

**教训**：使用 `String.includes()` 做类型名匹配时，必须警惕字符串被子串包含的情况。`formatting-em` 作为 `formatting-embed` 的子串，形成了一次经典的前缀匹配误伤。对于以连字符分隔的层级命名，建议使用完整词边界匹配或增加反向排除条件。

### 错误 8：Obsidian 1.14 起，隐藏 HTML 标签会把标签内的内容一起吞掉

**现象**：开启「隐藏 HTML 标签」后，`<font color="#ff0000">文字</font>`、`<del>文字</del>` 整段消失（连标签内的文字都不显示）；关闭该开关一切正常。升级 Obsidian（实测 1.14.5）后出现。

**原因**：Obsidian 实时预览对整段内联 HTML 自己就下了一个 `Decoration.replace`，把它换成 `span.cm-html-embed` widget（见 app 内 `u8` widget + `hmd-html-begin` / `hmd-html-end` 的高亮解析）。我们再用 `Decoration.replace` 去盖标签文本，两个 replace 区间嵌套重叠，CM6 构建行视图时对同一段文本重复推进文本迭代器，导致整段内容被吞。

**解决**：HTML 标签改用 `Decoration.mark` + CSS 隐藏字形，不用 `Decoration.replace`：

```css
.markdown-source-view.mod-cm6 .sh-html-tag-hidden {
    font-size: 0;
    letter-spacing: 0;
    color: transparent;
}
```

mark 不参与「替换区间」的计算，与 Obsidian 自己的 replace widget 可以共存：Obsidian 渲染 widget 时看不见标签（本来也不需要）；光标进入该段、Obsidian 退回源码显示时，mark 让标签字形宽度归零，同样看不到。

**教训**：在别人的编辑器里加 `Decoration.replace` 前，先确认那个区间有没有被宿主自己 replace 掉。跨扩展嵌套的 replace 是未定义行为，用 mark + CSS 更安全。

## 关键技术点

### CM6 装饰优先级

使用 `Prec.high()` 包裹 ViewPlugin，确保装饰优先级高于 Obsidian 内置的"光标移入时显示"逻辑：

```typescript
export function createFormatHiderExtension() {
    return Prec.high(
        ViewPlugin.fromClass(..., { decorations: (v) => v.decorations })
    );
}
```

### 光标排斥模式

不使用传统的"光标进入时显示、离开时隐藏"方式，而是采用"始终隐藏 + 光标排斥"策略：
- `buildDecorations()` 在每次 `update()` 时无条件重建，不检查光标位置
- `correctCursorAfterClick()` 在鼠标点击后将光标推到标记区域外
- 使用 `queueMicrotask` 异步执行修正，避免干扰原始事务

### 配置同步架构

```
┌─────────────────┐
│  settings.ts    │  定义接口 + 默认值
└────────┬────────┘
         │
┌────────▼────────┐
│   main.ts       │  loadSettings/saveSettings → syncConfig
└────────┬────────┘
         │ Object.assign
    ┌────┴────┐
    ▼         ▼
┌────────┐ ┌────────┐
│format- │ │white-  │
│hider   │ │space   │  模块级可变配置对象
│Config  │ │Config  │
└────┬───┘ └────┬───┘
     │          │
     ▼          ▼
  ViewPlugin.update()  每帧读取最新配置
```
