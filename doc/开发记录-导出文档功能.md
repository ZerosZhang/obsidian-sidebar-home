# 开发记录：文档导出（Markdown + 资源）

## 需求概述

新增一个命令面板命令「导出文档（Markdown + 资源）」：把**当前文档**导出到 Obsidian 库**外**的文件夹。正文存为 `.md`，正文里引用的图片与其他文件统一放进资源子文件夹，链接改写成标准 Markdown 相对链接，使导出物脱离 Obsidian 后仍可用。

### 功能清单

| 功能 | 说明 |
|------|------|
| 导出正文 | 当前 `.md` 写入 `<目标>/<文档名>/<文档名>.md` |
| 导出引用文件 | 图片、其他 `.md`、`.excalidraw.md`、`.xlsx` 等统一复制进 `assets/`（名字可配置） |
| 链接重写 | `![[图.png]]` → `![](assets/图.png)`；`[[笔记\|别名]]` → `[别名](assets/笔记.md)` |
| 覆盖保护 | 目标已有同名文件时弹窗询问「覆盖 / 跳过 / 取消」 |
| 目录选择 | 系统文件夹选择框；拿不到时退化为设置项里手填绝对路径 |
| 设置项 | 第 7 个设置 Tab「导出」，2 个设置项 |

### 需求讨论阶段定下的六个决策

先讨论方案、再动手，六个点都在动工前定死了：

| 决策项 | 结论 | 理由 |
|--------|------|------|
| 导出目的地 | 库外文件夹，走 Node `fs` | 导出物不该混进 Obsidian 索引；`vault.create*` 只能写库内 |
| 目录层级 | `<目标>/<文档名>/` 下放正文 + `assets/` | 多次导出不互相覆盖，一个文件夹就是完整包 |
| 引用文件归置 | 全部平铺进 `assets/` | 结构最简单；镜像原路径会出现很深的嵌套 |
| 递归深度 | 只导一层 | 行为可预期，导出体积可控 |
| 链接形式 | 标准 Markdown 相对链接 | 脱离 Obsidian 也能正常显示 |
| 覆盖策略 | 已存在则弹窗询问 | 反复导出时不会静默盖掉手动改过的文件 |

「只导一层」的代价要说清楚：**被引用的 `.md` 是原样复制、不重写其内部链接**。它在导出包里再引用的图片不会跟过来，那些链接会指向原地。

## 最终方案

### 产物结构

```
<导出目标文件夹>/
└── 我的笔记/                  ← 以当前文档名建子文件夹
    ├── 我的笔记.md            ← 正文，链接已重写
    └── assets/                ← 名字由「资源文件夹名」设置项决定
        ├── 图片1.png
        ├── 另一篇笔记.md
        ├── 流程图.excalidraw.md
        └── 数据.xlsx
```

### 文件结构

```
src/export/
  export-config.ts    ← 模块级配置 + 扩展名判定（getExtension / isImagePath / getDisplayName）
  link-scanner.ts     ← 扫描正文引用，纯逻辑
  export-planner.ts   ← 文件名清理与去重，纯逻辑
  link-rewriter.ts    ← 链接重写，纯逻辑
  export-runner.ts    ← 编排：读正文 → 解析 → 规划 → 落盘 → 重写
  conflict-modal.ts   ← 覆盖确认弹窗
  folder-picker.ts    ← 系统文件夹选择 + 资源管理器打开
main.ts        ← 注册命令、syncConfig 写入 exportConfig
settings.ts    ← exportTargetFolder / exportAssetsFolder
setting-tab.ts ← 第 7 个 Tab「导出」
```

### 处理流程

1. `editorCallback` 的 `ctx.file` 校验为 `.md`，`vault.cachedRead` 读正文。
2. `scanLinks()` 扫出三种语法的引用：`![[嵌入]]`、`[[wiki 链接]]`、`[文字](路径)`，各自记下**原文起止偏移**。
3. 逐条 `metadataCache.getFirstLinkpathDest(linkpath, sourcePath)` 解析成 `TFile`。
4. 库内目标按路径**去重**后，统一 `assignUniqueNames()` 分配 `assets/` 里的名字。
5. 目标目录不存在则 `fs.mkdir(recursive)`；已存在同名文件则弹窗询问。
6. `vault.readBinary()` → `Buffer.from()` → `fs.writeFile()` 复制资源；正文重写后用 `fs.writeFile(utf8)` 写出。
7. Notice 汇总「写入 N 个 / 跳过 N 个 / 失败 N 个」。

### 链接重写规则

| 原文 | 导出后 |
|------|--------|
| `![[图.png]]` | `![](assets/图.png)` |
| `![[图.png\|300]]` | `<img src="assets/图.png" width="300">` |
| `[[笔记]]` | `[笔记](assets/笔记.md)` |
| `[[笔记\|别名]]` | `[别名](assets/笔记.md)` |
| `[[笔记#小节]]` | `[笔记](assets/笔记.md#小节)` |
| `![[流程图.excalidraw]]` | `[流程图.excalidraw](assets/流程图.excalidraw.md)` |
| `![[数据.xlsx]]` | `[数据.xlsx](assets/数据.xlsx)` |
| `[文字](路径/图.png)` | `[文字](assets/图.png)` |
| `![图](笔记.md)` | `[图](assets/笔记.md)`（嵌入非图片会把 `!` 去掉，否则渲染成坏图） |
| 外链 / 解析不到的引用 | 原样保留，不报错 |

## 关键取舍

### 为什么走 Node `fs` 而不是 `vault` API

`vault.create()` / `vault.createBinary()` 只能写库内路径。导出到库外是需求的前提，只能用 `fs`。`fs` / `path` 是 Node 内置模块，已在 `esbuild.config.mjs` 的 `external` 列表里（由 `builtin-modules` 提供），不会被打进 bundle；`manifest.json` 已是 `isDesktopOnly: true`。

副作用：如果用户在设置里把导出目标填成**库内**路径，`fs` 写进去的文件不会立刻进入 Obsidian 的文件列表（要等重新扫描）。runner 会检测并弹一条提示，但不阻止。

### 为什么 Excalidraw / Excel 都原样复制

需求里明确说「以独立的文件形式导出」。转格式（Excalidraw 导 PNG/SVG）需要依赖 Excalidraw 插件的 API，会把本插件的可用性绑到另一个插件上。原样复制的代价是导出包里的 `.excalidraw.md` 需要装 Excalidraw 才能查看，这是用户已知并接受的。

### 链接里只编码会破坏语法的字符

`encodePath()` 只转义 `% # ? 空格 ( )`，中文保持原样。理由：`assets/图%20(1).png` 这类编码是必须的（空格与括号会让部分 Markdown 解析器提前闭合链接），但把中文也转成 `%E6%88%91` 会让原始 Markdown 完全没法读，收益为零。

### `\|` 是别名分隔符，不是文件名里的竖线

Obsidian 在表格里必须写成 `![[文件\|别名]]`，此时 `\|` **仍然**是别名分隔符，只是被转义以免表格拆列。所以 scanner 遇到竖线一律切分（不论是否带反斜杠），再把 head 末尾那个转义反斜杠去掉。这条是离线断言跑出来的——最初按「转义竖线 = 字面竖线」实现，`[[文件\|别名]]` 被解析成了文件名 `文件|别名`。

同理，`[[笔记#小节]]` 无别名时，显示文本取笔记名 `笔记` 而不是 `笔记#小节`，与 Obsidian 自身的显示一致。

### 资源名去重

不同目录下的同名文件会挤进同一个 `assets/`。`assignUniqueNames()` 按出现顺序加 ` (1)`、` (2)` 后缀，比较时忽略大小写（Windows 文件系统不区分），并保留扩展名位置——`图.excalidraw.md` 的序号插在 `.excalidraw` 之后：`图.excalidraw (1).md`。

`sanitizeName()` 另外处理 Windows 非法字符（`< > : " / \ | ? *`）、结尾的点与空格、以及 120 字符的长度上限。

### 目录选择器的降级

Obsidian 没有提供目录选择 API。这里走 `require('electron').remote.dialog.showOpenDialog`，并兼容「返回 Promise」与「回调」两种签名，另有 180 秒超时兜底。新版 Electron 移除了内置 `remote`，**拿不到时返回 `null`**，UI 上提示用户改在「设置 → 导出 → 导出目标文件夹」里手填绝对路径——这条路径不依赖任何 Electron API，是始终可用的正路。

## 验证

### 可离线验证的部分（已完成）

`link-scanner` / `export-planner` / `link-rewriter` 三个模块不依赖 Obsidian 运行时，按 Excel 预览那套办法离线跑断言：

```bash
node node_modules/esbuild/bin/esbuild verify-export.tmp.ts --bundle --platform=node --format=cjs --outfile=verify-export.tmp.cjs
node verify-export.tmp.cjs
```

**73 项断言全部通过**，覆盖：

- 三种链接语法的解析、别名、子路径、尺寸参数、转义竖线、百分号转义
- 围栏代码块与行内代码里的链接**不**被当成引用
- 同一行多个链接的偏移不串位（断言 `raw === text.slice(start, end)`）
- 文件名清理、` (n)` 去重、双扩展名序号位置
- 每种重写规则的输出、空格与括号编码、未解析链接保持原样
- 多链接一次性替换（从后往前替换，避免偏移错位）

验证脚本是一次性的，跑完即删，不入库。
