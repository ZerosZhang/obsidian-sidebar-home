# 开发记录：Edge-TTS 语音朗读功能

## 需求概述

在 Sidebar Home 侧边栏底部集成语音朗读控制面板，使用微软 Edge 浏览器的神经网络 TTS 引擎（Edge-TTS）将 Markdown 笔记转换为高质量音频朗读。

### 功能清单

| 功能 | 说明 |
|------|------|
| 全文朗读 | 通过 WebSocket 直连微软 Edge-TTS 服务，生成 MP3 音频播放 |
| 选中朗读 | 从选中文本所在句子开始朗读到文末 |
| 暂停/继续/停止 | 侧边栏按钮控制播放状态 |
| 分批流式生成 | 大文本分批请求，第一批秒级就绪 |
| 句子高亮 | CM6 Decoration 实现，不影响编辑器选区 |
| 离线降级 | Edge-TTS 不可用时自动切换到 Web Speech API |
| 本地音色选择 | 扫描系统 SpeechSynthesis 语音列表 |
| Edge-TTS 音色选择 | 15 种神经网络语音可选 |
| 语速调节 | 设置面板滑块 0.5x ~ 2.0x |
| 高亮颜色自定义 | hex 颜色输入 + 恢复默认按钮 |

```
src/

```

### 双引擎策略

| 引擎 | 用途 | 特点 |
|------|------|------|
| Edge-TTS | 全文朗读 | 神经网络音质，可缓存，需联网 |
| Web Speech API | 选中朗读 / 离线降级 | 即时响应，不需要网络 |

## 错误记录与解决方案

### 1. `getActiveViewOfType(MarkdownView)` 返回 null

**问题**：侧边栏按钮点击后拿不到当前编辑器的 Markdown 视图。

**原因**：esbuild 将 `MarkdownView` 类引用打包后，与 Obsidian 运行时的实例 `instanceof` 不匹配。

**解决方案**：改用两层 fallback——
1. 先调 `getActiveViewOfType(MarkdownView)`（修复后可用）
2. 若 null，遍历 `getLeavesOfType('markdown')`，通过 `offsetParent !== null` 找到可见的 leaf

**文件**：`sidebar-view.ts:getMarkdownView()`

---

### 2. 浏览器 WebSocket 无法连接 Edge-TTS（TLS 层拒绝）

**问题**：`new WebSocket('wss://speech.platform.bing.com/...')` 直接失败。

**原因**：浏览器 `WebSocket` API 不允许设置自定义 HTTP 请求头。Edge-TTS 服务端校验 `Origin`、`User-Agent` 等头信息，Chromium 发的与 Edge 浏览器不匹配，服务端拒绝 TLS 握手。

**解决方案**：改用 Node.js 内置 `tls` 模块建立原始 TLS 连接，手动发送 HTTP Upgrade 请求，完全控制请求头。

```typescript
// 手动模拟 Edge 浏览器的请求头
const req = [
    `GET ${path} HTTP/1.1`,
    `Origin: chrome-extension://jdiccldimpdaibmpdkjnbmckianbfold`,
    `User-Agent: Mozilla/5.0 ... Edg/143.0.0.0`,
    `Sec-WebSocket-Key: ${wsKey}`,
    ...
].join('\r\n');
```

**文件**：`edge-tts.ts`

---

### 3. 401 Unauthorized（HTTP 层拒绝）

**问题**：TLS 握手成功后，HTTP Upgrade 返回 401。

**原因**：
- `TrustedClientToken` 末尾字符错误（`C6F4` → 应为 `D6F4`）
- 缺少 `Sec-MS-GEC` DRM 令牌
- `Sec-MS-GEC` 应放在 URL 查询参数中，而非 HTTP 头

**解决方案**：实现 `generateSecMsGec()` 函数，完整对齐 Python edge-tts 的 DRM 算法：
1. 取当前 Unix 时间 → 加 Windows 纪元偏移 → 向下取整到 5 分钟
2. 转为 100 纳秒间隔 → 拼接 TrustedClientToken → SHA256 → 大写 hex
3. 同时添加 `ConnectionId` 和 `Sec-MS-GEC-Version` 查询参数

**文件**：`edge-tts.ts:generateSecMsGec()`

---

### 4. 101 握手成功但音频数据超时（Close 帧被忽略）

**问题**：HTTP Upgrade 101 成功后，没有收到音频数据便超时。

**原因**：服务端发送了 Close 帧（opcode `0x08`）关闭连接，但 `parseFrames` 未处理 Close 帧导致静默丢弃。

**解决方案**：在 `parseFrames` 中增加 opcode `0x08` 处理，解析 close code 和 reason：
```typescript
if (opcode === 0x08) {
    let closeCode = 0, closeReason = '';
    if (payloadLen >= 2) closeCode = payload.readUInt16BE(0);
    if (payloadLen > 2) closeReason = payload.slice(2).toString('utf-8');
    frames.push({ type: 'text', data: `CLOSE:${closeCode}:${closeReason}` });
}
```

**文件**：`edge-tts.ts:parseFrames()`

---

### 5. `turn.end` 后 `ECONNRESET` 导致音频丢失

**问题**：服务端发送 `Path:turn.end` 后，代码调用 `socket.end()` 正常关闭连接，但服务端先断开导致 `ECONNRESET`，已收集的音频数据被丢弃。

**原因**：`socket.on('end')` 回调在 `ECONNRESET` 后触发，但 `closed` 标志可能已设置，导致既不 resolve 也不 reject。

**解决方案**：收到 `turn.end` 后立即 resolve Promise（音频数据已全部收到），不再等 socket 正常关闭。用 `socket.destroy()` 替代 `socket.end()` 强制断开。

**文件**：`edge-tts.ts`

---

### 6. SSML 双重嵌套

**问题**：TTS 引擎读出 `http`、`xml`、`break time=100ms` 等标签文字。

**原因**：`tts-player.ts` 的 `buildBatchSsml()` 已构造完整 `<speak>...</speak>` XML，但 `edge-tts.ts` 的 `generateEdgeTts()` 又调用 `buildSsml()` 包了一层，产生嵌套 SSML。TTS 引擎把内层标签当正文朗读。

**解决方案**：去掉 `edge-tts.ts` 中的 `buildSsml()` 调用，直接使用传入的完整 SSML 字符串。

**文件**：`edge-tts.ts:generateEdgeTts()`

---

### 7. `<break>` 标签导致 `SSML is invalid`

**问题**：包含 `<break time="100ms"/>` 的 SSML 被服务端以 `1007:SSML is invalid` 拒绝。

**原因**：微软 Edge-TTS 实现不允许标准 W3C `<break>` 标签（即使是最简形式的 `<break/>`）。

**解决方案**：用中文句号 `。` 连接句子，完全去掉 `<break>` 标签。同时去掉 `xmlns:mstts` 命名空间（Python 版也没用）。

**文件**：`tts-player.ts:buildBatchSsml()`

---

### 8. 多批次 MP3 拼接不可播放

**问题**：将多个 Edge-TTS 批次的 MP3 数据直接 `Buffer.concat` 后 `<audio>` 无法播放。

**原因**：直接拼接多个独立的 MP3 文件可能导致格式损坏。

**解决方案**：不拼接 MP3。改为串联播放——每个批次独立创建 `Audio` 元素，`ended` 事件触发后自动切换到下一批。

**文件**：`tts-player.ts:playLoop()`

---

### 9. 无效 XML 字符导致 SSML 被拒

**问题**：某些 Markdown 文本转换后包含控制字符（`\x00-\x08`, `\x0b-\x0c`, `\x0e-\x1f`），导致 XML 解析失败。

**原因**：XML 1.0 不允许大部分 ASCII 控制字符出现。

**解决方案**：对齐 Python edge-tts 的 `remove_incompatible_characters`，添加 `sanitizeText()` 函数过滤控制字符。

**文件**：`tts-player.ts:sanitizeText()`

---

### 10. `editor.setSelection()` 高亮干扰编辑 + 阅读模式无效 + HTML 标签偏移

**问题**：
- 使用 `editor.setSelection()` 做高亮，光标会跳转，无法同时编辑
- 阅读模式下没有 Editor，高亮不生效
- 文档中包含 `<mark>` 等 HTML 标签时，`indexOf` 搜索失准

**解决方案**：改用 CM6 `Decoration.mark()` 叠加背景色，不影响选区。
- 创建 `tts-highlight.ts`：`StateField` 存储高亮范围 + `ViewPlugin` 渲染 Decoration
- 编辑/阅读模式均生效
- `findSentenceOffsets` 重写：在 raw markdown 中匹配纯文本句子时跳过 `<...>` HTML 标签

**文件**：`tts-highlight.ts`, `sentence-splitter.ts:findSentenceOffsets()`

---

### 11. 重复点击产生多个重叠播放

**问题**：播放过程中再次点击朗读按钮，旧的 `playLoop` 未被取消，两个声音同时播放。

**原因**：`stop()` 只停了 Audio 元素，但 async `playLoop` 循环仍在运行。

**解决方案**：添加 `aborted` 标志位。`stop()` 设为 `true`，`playLoop` 每轮循环和每批次 `ended` 后检查该标志，立即退出。

**文件**：`tts-player.ts`

---

### 12. 侧边栏按钮点朗读始终取第一个标签页

**问题**：打开多个标签页时，无论在哪个标签页点朗读，始终读第一个标签页内容。

**原因**：`getMarkdownView()` 遍历 markdown leaves 时取了第一个，未判断哪个是当前活跃/可见的。

**解决方案**：三层查找逻辑——
1. `getActiveViewOfType(MarkdownView)` 
2. 遍历找 `offsetParent !== null` 的可见 leaf
3. fallback 到第一个

**文件**：`sidebar-view.ts:getMarkdownView()`

---

### 13. 音色名混用

**问题**：用户在设置中选的 Web Speech 音色名（如 `Microsoft Yaoyao - Chinese (Simplified, PRC)`）被传入 Edge-TTS SSML，导致语音错误或失败。

**原因**：`settings.ts` 中 `ttsVoice` 字段同时被 Web Speech 和 Edge-TTS 使用，但两者音色命名体系完全不同。

**解决方案**：新增独立字段 `ttsEdgeVoice`（默认 `zh-CN-XiaoxiaoNeural`），Edge-TTS 专用。`ttsVoice` 保持为 Web Speech 音色。

**文件**：`settings.ts`, `setting-tab.ts`, `tts-player.ts`

---
