# 开发记录 — 标签页复用与强制新标签页功能

> 日期：2026-07-21 | 版本：v2.2.0

## 概述

基于 `external/obsidian-open-in-new-tab-master` 参考插件，将 Open In New Tab（强制新标签页打开）与 sidebar-home 已有的 `reuseExistingTab`（复用已有标签页）合并为一个统一功能。同时修复 wiki 链接 `[[file]]` 不触发复用逻辑的 Bug。

**功能入口：** 设置页 → 标签页设置 → 「复用已有标签页」开关。

---

## 1. 架构设计

### 1.1 文件结构

```
obsidian-sidebar-home/
├── tab-utils.ts    ← 新增：标签页复用核心逻辑（2 个导出函数）
├── main.ts         ← 修改：在 onload/onunload 中注册/清理
└── sidebar-view.ts ← 不变：侧边栏快链复用逻辑保持独立
```

### 1.2 三条路径覆盖

| 触发来源 | 处理方式 | 位置 |
|----------|----------|------|
| 编辑器 wiki 链接 `[[file]]` | 重写 `Workspace.prototype.openLinkText` | `tab-utils.ts:patchOpenLinkText()` |
| 文件浏览器点击 `.nav-file-title` | 捕获阶段 `click` 事件监听 | `tab-utils.ts:registerFileExplorerHandler()` |
| 侧边栏快捷链接点击 | `openFileInReadingMode()` 内置逻辑 | `sidebar-view.ts:497-525` |

### 1.3 行为矩阵

当 `reuseExistingTab = true`：

| 场景 | 文件是否已打开 | 行为 |
|------|--------------|------|
| wiki 链接（同文件锚点 `[[#标题]]`） | — | **透传原行为**，不干预 |
| wiki 链接（跨文件 `[[note]]`） | 已打开 | `setActiveLeaf` 跳转，原方法 `newLeaf=false`（保留标题跳转） |
| wiki 链接（跨文件 `[[note]]`） | 未打开 | 原方法 `newLeaf=true`（新建标签页） |
| 文件浏览器点击 | 已打开 | `stopPropagation` + `preventDefault` + `setActiveLeaf` |
| 文件浏览器点击 | 存在空白标签页 | `setActiveLeaf` 到空白页，不阻止默认行为 |
| 文件浏览器点击 | 未打开，无空标签页 | `stopPropagation` + `preventDefault` + `openLinkText(path,path,true)` |
| 侧边栏快链 | 已打开（rootSplit 内） | `revealLeaf` + `setActiveLeaf({focus:true})` |
| 侧边栏快链 | 未打开 | `getLeaf('tab')` + `openFile()` + 切换阅读模式 |

当 `reuseExistingTab = false`：全部透传 Obsidian 默认行为。

## 2. 踩坑记录

### 错误 1：monkey-around 导致 openLinkText 不触发

**现象：** 使用 `import { around } from 'monkey-around'` 的 `around(Workspace.prototype, { openLinkText(old) { ... } })` 方式 monkey-patch 后，点击 wiki 链接没有打开新标签页。

**分析：** `monkey-around` 的 `around1` 内部对原型方法做了多层 `setPrototypeOf` 包装。当 Obsidian 的 `Workspace` 类继承链较深（`Workspace extends Events`），`Object.getPrototypeOf(obj)[method]` 解析可能绕过被 patch 的方法；同时 `hadOwn` 判断在 Obsidian 的类结构中不稳定。

**解决：** 放弃 `monkey-around`，改用直接原型赋值 + 闭包保存原始引用：

```typescript
export function patchOpenLinkText(plugin: SidebarHomePlugin): () => void {
    const original = Workspace.prototype.openLinkText;
    Workspace.prototype.openLinkText = async function(...) {
        // ... 自定义逻辑
        return await original.apply(this, [...]);
    };
    return () => { Workspace.prototype.openLinkText = original; };
}
```

`onunload` 中调用返回的卸载函数恢复原始方法。

### 错误 2：路径严格比较导致跨文件夹匹配失败

**现象：** wiki 链接 `[[note]]` 指向 `folder/note.md`，`reuseExistingTab` 开启但已经打开的 `folder/note.md` 未被识别，每次点击都创建新标签页。

**原因：** 第一版使用 `viewState.state?.file === \`${fileName}.md\`` 做严格相等比较。在 Obsidian 中，`viewState.state.file` 存储完整相对路径（如 `folder/note.md`），而 wiki 链接解析出的 `fileName` 不含文件夹前缀（如 `note`），`===` 永远不匹配。

**解决：** 改用 `endsWith`：

```typescript
const file = (vs.state as { file?: string })?.file;
if (vs.type === 'markdown' && file?.endsWith(`${fileName}.md`)) {
    // 匹配成功
}
```

文件浏览器处理器使用 `===` 即可（因为 `data-path` 属性本身就是完整相对路径）。

---

### 错误 3：TypeScript `unknown` 类型阻塞编译

**现象：** `tsc -noEmit` 报错 `Object is of type 'unknown'`，指向 `vs.state?.file?.endsWith(...)`。

**原因：** `WorkspaceLeaf.getViewState()` 返回的 `ViewState` 接口中 `state` 字段类型为 `unknown`（Obsidian 类型声明为 `any` → `tsconfig` 中 `noImplicitAny: true` 迫使类型推断为 `unknown`），不能直接访问 `.file`。

**解决：** 使用类型断言：

```typescript
const file = (vs.state as { file?: string })?.file;
```

---

### 错误 4：`newLeaf='tab'` 字符串与 `newLeaf=true` 布尔值行为差异

**现象：** 参考插件使用 `openLinkText(path, path, true)`（布尔），第一版用 `'tab'`（字符串）。`'tab'` 在 `PaneType` 类型定义中合法，但实际行为可能因 Obsidian 版本而异。

**解决：** 统一使用 `true`（布尔），与参考插件 `openInNewTab` 及 `obsidian-no-dupe-leaves` 一致。Obsidian 的 `getLeaf(true)` 和 `getLeaf('tab')` 行为等价，但 `true` 历史更久、兼容性更好。

---

### 错误 5：文件浏览器已打开文件时仍调用 openLinkText

**现象：** 第一版在文件浏览器处理器的"找到已打开文件"分支中，调用 `workspace.openLinkText(path, path, false)`，导致我们的 `patchOpenLinkText` 再次被触发并执行重复的 `iterateAllLeaves`。

**解决：** 已找到文件时直接 `stopPropagation` + `preventDefault` + `setActiveLeaf`，不额外调用 `openLinkText`。
